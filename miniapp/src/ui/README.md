# Interface package

Screens import controls from this directory. `tokens.css` owns colour, type, spacing, density and motion; `styles.css` lists the parts in `parts/`, which own shared surfaces, control states and the native screen geometry; `desktop.css` owns the desktop column and the value triggers; the phone's pieces are in `primitives/drawer.tsx` (the drawer and its hamburger), `primitives/listpage.tsx` (section labels, chips, empty states, skeleton rows, banners) and `shell.tsx` (the top bar), and their rules sit in the phone blocks of the parts, inside the phone media query. `components.tsx` owns stateful choices, status and skeletons; `dialogs.tsx` owns temporary layers and their keyboard behavior. Theme preferences override these tokens for the entire application, including terminal colours.

Use existing behavior rather than rendering a second control that performs the same action. A page provides its data and callbacks. It does not implement its own choice menu, notification layer or settings row.

| Block | Contract |
| --- | --- |
| Button | Use `.btn` for an action, `.primary` (violet, the one per screen) for the next action, `.danger` for destruction. Height `--ctl-h` (32), gap 8 px, text 14 px, 8 px corners. Disable while submitting; preserve its label. |
| Icon button | Use `.iconbtn` with a translated accessible name and title. 32 px on desktop, 44 px on touch. An icon is not an action until it has a button or link. |
| Input | Use `.field`, a visible label and an adjacent error. Enter submits only an explicit form. Disabled fields retain the value. |
| Text area | Use `.field` for editing a setting; `Composer` for sending messages. Preserve multiline content and a visible focus boundary. |
| Choice | Use `Dropdown` for a long list; `Segmented` for short fixed choices. Composer choices use `ControlTrigger` and an anchored `Popover`. The caret is a separate 14 px icon. In the message toolbar, model and effort share one unboxed trigger with the caret at its end; other value controls retain their boundary. |
| Checkbox | A selection within a set uses a native labelled checkbox. Space toggles it; disabled is explicit. Do not use it for an action. |
| Switch | `Switch` applies a binary setting immediately; its accessible name is the setting, its checked state is the value. |
| Menu | `OverflowMenu` contains actions; context menus invoke these same commands at the pointer, clamped 8 px inside the viewport. Shift+F10 opens the focused element's menu. Arrow keys move, Enter chooses, Escape closes and restores focus. Do not replace a menu with a confirmation dialog. A row is a 16 px icon, an 8 px gap and the label on one line, the icon centred on it; a row with no icon keeps the text column of the rows around it. |
| List | Keep its own scroll container. Empty and loading states replace its body, never the navigation. Group headings are 12 px; ordinary row titles are 14 px. |
| List row | 32 px for one line (28 dense), 44 for a title over metadata, 56 for a large row. A selected notification opens its detail beside the list on a wide desktop and in the row on a smaller window. |
| Tabs | Use the existing tablist components with a selected state and keyboard handling. Scroll a long tab strip; do not scroll the page horizontally. |
| Badge | Count or state only, 12 px text. It never duplicates an action. Do not communicate failure through colour alone. |
| Toast | `toast` announces a result; use Undo only when the operation is actually reversible. A persistent failure belongs by its affected control. |
| Notice | `raiseNotice` is the pop-up for what happened while the operator was elsewhere: it queues (three in a desktop's corner, one banner on a phone), holds under a moving pointer, swipes away, and carries the buttons that answer it. Only the host's notification bridge (`toasts.tsx`) and the setting notices raise one. |
| Modal | `Sheet` for a task, `confirmDialog` for a consequential action. Tab stays inside; Escape closes only the top layer; focus returns to its opener. |
| Popover | `Popover` stays within the viewport, chooses above or below the opener and repositions on resize. Model choice starts with provider groups, local vector marks and model counts. A group shows only its own presets; Back or ArrowLeft returns to groups, Escape closes. Search at the root spans all providers; search inside a group stays scoped. Effort is a row in this same picker, with a child panel to its right or left when space allows, and an inline panel in a narrow sheet. Escape closes the child first; ArrowRight opens it, ArrowLeft returns. Custom model entry is an explicit expandable action. Arrow editing stays in the search field and ArrowDown enters choices. |
| Banner | Use the existing offline, maintenance, fallback and change strips. Keep actionable failures readable until resolved. |
| Empty state | Say what appears here and offer one next action. A sidebar that already has New does not repeat the same button in its empty body. |
| Skeleton | `Skeleton` reserves the expected row geometry while loading. Keep retry distinct from loading. Motion respects the application and OS preference. |
| Agent activity | Preserve the existing compact hierarchical tree, grouped calls, detail expansion and result previews. Do not turn each tool call into a large card. |
| File diff | Preserve the native file diff, line numbers, context and expansion. Code uses `--mono` and `--fs-mono`; readable content may scroll within the diff. |
| Sidebar | The whole of the desktop's navigation, no icon rail beside it: 300 px wide, a 52 px head (mark, mode menu, search, fold), the pinned rows (New chat, the operator's destinations, More), the mode's list, a 52 px foot (account, Settings). Every row is one 32 px line with its text 12 px in; a chat's state is a word at its right edge, its model and host in its tooltip. The filters are one menu on the "Chats" label; never put a grid of tabs or chips above the list. Drag the single outer edge to resize it between 232 and 360 px. Folded, it is gone and one button in the window's corner brings it back. The selection and width persist across routes. |
| Header | `PageHeader` is one 52 px row: the page's name, its filters, its actions at the right edge; `ruled` draws the line under it. `Page` is the column under it (`list`, `reading`, `full`). Do not add a second row of metadata to conversation headers. |
| More launcher | `Launcher` (`navmenu.tsx`) in the `Popover` primitive, a `dialog` 560 px wide, 8 px from the sidebar's edge and level with its More row: a 40 px search field that narrows the destinations (words that match none go on to the palette), Frequent chips, every screen and page in its group (Work, Autonomy, Knowledge, Observe, Pages) as 44 px rows in two columns with a line saying what each is, and a pin on each that writes `[navigation] pinned` (on a phone, the drawer's list). Arrows walk rows and pins as one grid, Tab goes group to group. |
| Command palette | `Palette` (`palette.tsx`) in the `Sheet` and `Combobox` primitives, 640 px wide, high in the window: a 48 px field, groups (Chats, Projects, Actions, Go to, Settings) of 36 px rows under 28 px labels, a 36 px foot with the keys. Chats are found by name and, through the host's search, by meaning; Settings from the settings index. Enter opens, Ctrl Enter opens a chat beside the open one, Tab goes group to group. |
| Message field | Existing `Composer`: one common width with the timeline, text above controls, mode on the left, model/effort on the right within the shared field boundary, attachments and voice progress, primary send/stop action with an 8 px radius. The toolbar reserves 32 px on desktop and 44 px for a touch pointer; voice and Send use the same slot, and typing one line cannot resize it. The field uses 12 px insets, an 8 px gap and a 40 px minimum text area. Retain draft, approval, questions and queued steer behavior. |

Defaults use the named theme already chosen by the operator; a theme recolours the neutral frame and never an accent. Three accents carry one meaning each: violet (`--accent`, `--primary`) is what is selected and the one primary action, cyan (`--live`, also `--ok` and `--info`) is running, live or added, orange (`--attention`, also `--warn` and `--bad`) needs the operator, has full access or was removed; no other hue is chrome, and nothing glows. Hover is `--hover`, a chosen row `--selected`, keyboard focus a 2 px violet outline, and disabled controls cannot activate. Error states retain the attempted value. Loading controls do not move neighboring controls. Use 4/8/12/16/24 px spacing steps. Type is Inter, code JetBrains Mono, both bundled: 14 px for controls, lists and rows, 15 for reading text and a page's title (15/600), 13 for secondary text, 12 for meta and labels and never smaller; 18/500 for a pane or section title and 28/500 only for a page's hero; weights 400, 500 and 600. Rows are 32 px, dense rows 28; corners are 8 for a control, 12 for a card, 14 for what floats and 20 for the composer; what floats has a 1 px `--line-strong` edge and the one floating shadow, and cards lie flat. Below 1024 px the scale is the phone's six steps, 12/13/14/15/16/17 (15 px row titles, 12–13 px meta, a 16 px bar title, 17 px sheet titles, 16 px text fields), with 44 px targets, a 52 px top bar, 54 px rows with a meta line and 44 px rows without, 28 px chips and a 44 px idle composer; a row shows a second line only when it adds something, and every list of providers leads each row with the provider's mark; a phone screen is drawn from `phone.tsx` rather than from desktop controls in phone sizes.

At half a desktop window, retain complete text and usable controls. Panels and lists scroll internally; popovers stay inside the viewport. Reduced motion disables nonessential animation without delaying input. The optional native companion is off until enabled in Appearance; it receives a small status enum and never receives credentials or conversation text.
